# 002 · 技术选项范围纳入「完成栈」

> 双角色沟通纪要 · 产品经理主导  
> 参考图：Apple Music / Spotify / Linear / Vercel（用户提供）

## 1. 目标

把已对齐的**体验参照与部署/协作工具**写入双角色「技术选项范围」，后续选型与验收可直接引用，避免口头漂移。

## 2. 范围

| 做 | 暂不做 |
|---|---|
| 将四项纳入正式选项目录（见工程侧《技术选项范围》） | 本刀不重做整站 UI、不强制立刻迁 Vercel |
| 明确：哪些是**体验硬参照**，哪些是**工程可选实现** | 不要求 1:1 像素复刻 Apple/Spotify |

## 3. 关键路径

不影响当前用户听歌主链；仅约束后续「做 UI / 部署 / 协作追踪」时的默认参照池。

## 4. 硬约束

| 项 | 角色归属 | 约束 |
|---|---|---|
| **Apple Music** | 产品体验参照 | 侧栏导航 + 发现流 + **顶栏/全局播放区** 信息架构可借鉴 |
| **Spotify** | 产品体验参照 | 侧栏曲库/歌单 + **底栏全局播放器** + 歌单网格可借鉴 |
| **Linear** | 体验密度 + 协作节奏参照 | 信息密度、列表层级、筛选与「问题/切片」推进感；非音乐业务本身 |
| **Vercel** | 部署选项（推荐） | 上线/预览/环境变量等部署路径进入可选池；与现有 Django 并存时须写清偏差 |

补充：

- 暗色、侧栏 + 主内容 + **常驻播放器** 为体验底线方向（播放器顶/底由工程在范围内自选）。
- 旧 Mayday（Django）可继续承载 API/扫描；前端形态向上述参照演进时，工程自选渐进或并行，须回写选型记录。
- **时间线功能已废弃**（纪要 001），不得借 Apple/Spotify 的「时间线」叙事回潮。
