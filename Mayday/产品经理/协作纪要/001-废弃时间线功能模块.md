# 001 · 废弃时间线功能模块

> 双角色沟通纪要 · 产品经理主导

## 1. 目标

明确：**时间线 / 时间隧道**不再作为产品功能；衔接开发以「扫描 → 曲库展现 → 播放 → 歌单/用户」为主链。

## 2. 范围

| 做 | 暂不做 / 废弃 |
|---|---|
| 下线时间线导航、文案与聚合 API | 专辑时间线主线叙事 |
| 拆除 `TimelineRepository` 聚合模块 | 以时间隧道整合巡回/言论/图片的产品路径 |
| 保留 Album / Song / 播放 / 歌单 / 扫描等能力 | — |
| Tour / Quote / Image 数据模型可暂留（非时间线入口） | 不以时间线形式对外呈现 |

## 3. 关键路径（更新后）

```
进入站点 → 曲库/搜索发现 → 播放 → 连续播放
→ 收藏/歌单 → 登录沉淀 →（后续）会员
```

不再经过：时间隧道浏览页 / `#timeline` 锚点。

## 4. 硬约束

- 不得再把时间线作为 MVP 验收项或首页主叙事。
- 工程拆除须去掉用户可见入口与 `/api/timeline/`；不得静默留死链。
- 底层 Album 等实体仍服务曲库与播放，不因废弃时间线而误删曲库能力。

## 5. 验收标准

- [x] 导航无「时间隧道」入口；站点 slogan 不再主打时间隧道。
- [x] `GET /api/timeline/` 已移除。
- [x] `mayday_app/timeline.py` 及专属序列化/分页已移除。
- [ ] 首页曲库、播放、歌单等非时间线能力仍可用（人工冒烟）。
