# 006 · 第四刀切片：会员骨架

> 双角色沟通纪要 · 产品经理主导  
> 前置：004 登录+歌单隔离 · 005 音量  
> 对齐：《初步的项目计划》免费/会员分层（本刀只做骨架，不做真实支付）

## 1. 目标

让可识别用户看到**免费 / 会员**身份，能走通「升级会员」演示路径（mock），并用**一条可感知权益门控**证明分层生效。

## 2. 范围

| 做 | 暂不做 |
|---|---|
| 会员资料模型（plan + 到期时间 + 是否有效） | Stripe / 国内支付 / Webhook |
| 会员页：状态展示 +「升级会员（演示）」 | 高清音质、推荐、去广告真实实现 |
| 侧栏入口；API：状态查询 + mock 升级 | 运营后台完整会员管理 UI |
| **门控**：免费用户歌单数上限（建议 5）；会员不限 | 复杂套餐矩阵、年/月自动续费 |

## 3. 关键路径

```
登录 → 侧栏「会员」→ 看到当前为免费
 → 点「升级会员（演示）」→ 状态变为会员（有到期日）
 → 可创建超过免费上限的歌单
 →（可选）到期后回落免费逻辑（本刀可用手动改期或短演示期验收）
```

## 4. 硬约束

- 升级必须登录；禁止未登录开通。
- Mock 升级须在 UI 标明「演示 / 非真实扣款」。
- 门控失败返回可理解错误（如「免费用户最多 5 个歌单，请升级会员」）。
- 不引入支付密钥进仓库。

## 5. 验收标准

- [x] 登录用户可打开会员页，看到 plan 状态。
- [x] Mock 升级后 plan=member 且 `is_active` 为真。
- [x] 免费用户创建第 6 个歌单被拒绝（403 + upgrade_required）；会员可通过。
- [x] 侧栏有会员入口；文案标明演示非真实扣款。

冒烟：membership 200；status free；第6歌单 403；upgrade 200；之后创建 201；匿名页 302 / upgrade 401。
