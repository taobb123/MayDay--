# 004 · 第二刀切片：歌单按用户隔离

> 双角色沟通纪要 · 产品经理主导  
> 前置：003 应用壳（登录已恢复）

## 1. 目标

登录用户只能看见、创建、改、删**自己的歌单**；未登录访问「我的歌单」或写操作时被引导登录。  
闭合主链中的：**登录 → 个人歌单沉淀**。

## 2. 范围

| 做 | 暂不做 |
|---|---|
| 列表/详情/CRUD/加曲按 `request.user` 过滤与鉴权 | 会员、分享公开歌单、协作歌单 |
| 「我的歌单」页与详情页需登录 | 音量条、UI 大改 |
| 同名校验改为**同一用户内**唯一（模型已有 unique_together） | 迁移历史脏数据归属策略以外的清理工具 |
| API 未登录返回 401 + `login_required`；前端提示去登录 | Next / Vercel |

## 3. 关键路径

```
未登录点「我的歌单」→ 登录页（可带 next）
 → 登录成功回歌单页 → 只见自己的歌单
 → 创建歌单 / 加曲 → 仅写入本人歌单
 → 另一账号登录 → 看不见上一账号歌单
```

## 4. 硬约束

- 禁止再使用 `User.objects.first()` 作为歌单归属。
- 禁止未登录创建/改/删/加曲。
- 不得通过改 URL 的 playlist_id 操作他人歌单（须校验归属，404/403）。
- 曲库浏览与播放仍允许游客。

## 5. 验收标准

- [x] 用户 A 的歌单列表不含用户 B 的歌单。
- [x] 未登录访问 `/playlists/` 跳转登录（302）。
- [x] 未登录调用创建/加曲 API → 401。
- [x] 登录后创建歌单 `user` 为当前用户；跨用户改他人歌单 → 404。

冒烟（2026-08-12）：双用户创建/列表隔离；匿名 list/create=401；页=/playlists/→302；跨用户 update=404。
