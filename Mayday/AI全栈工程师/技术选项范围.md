## 一、已纳入的「完成栈」参照

| 选项 | 类型 | 在本项目中的用途 | 非用途 |
|------|------|------------------|--------|
| **Apple Music** | UX / IA 参照 | 侧栏（For You / Browse / Library）+ 主区发现卡片 + **顶栏播放控件** 布局语言 | 不要求接入 Apple 账号/曲库；不复刻 Beta 品牌 |
| **Spotify** | UX / IA 参照 | 侧栏（Home / Search / Library / Playlists）+ 歌单网格 + **底栏全局播放器** | 不要求 Spotify API；不复刻品牌绿与完整社交 |
| **Linear** | 体验密度 + 协作参照 | 列表密度、分组、筛选、Issue/切片推进节奏；暗色极简控件手感 | 不把 Issue Tracker 做成音乐产品主界面；Favorites 里的 timeline 与已废弃时间线无关 |
| **Vercel** | 部署 / 预览平台 | Web 前端或 BFF 的 CI/CD、预览 URL、环境变量、域名；可与 GitHub 联动 | 不强制本刀立刻迁站；Django 单体可暂留本地/其他主机，迁站时写偏差 |

## 二、体验底线（产品约束，工程须满足）

1. **三区结构**：左导航 · 主内容 · 常驻播放器（顶栏或底栏二选一或可切换，须全局状态）。
2. **暗色优先**：深底、高对比标题、低对比次要信息；强调色克制使用。
3. **播放器全局化**：切页不丢播放状态；含进度、上一首/下一首、音量、队列入口。
4. **曲库/歌单可扫视**：卡片或列表密度参考 Spotify/Apple，避免杂乱仪表盘感。

## 三、实现栈选项池（工程自主，示例非强制）

与《初步的项目计划》对齐、且不与上表冲突的常用组合：

| 层级 | 选项池 | 备注 |
|------|--------|------|
| 前端 | 现有 Django 模板渐进增强；或 **Next.js + TypeScript** | 大改 UI 时优先评估 Next |
| 样式/组件 | **Tailwind CSS + shadcn/ui** | 贴近 Linear 密度与 Spotify/Apple 卡片 |
| 播放状态 | Zustand / 现有前端状态方案 | 须支撑全局播放器 |
| 音频 | HTML5 Audio API | 延续 |
| 后端 | **现有 Django + DRF**；或 Next Route Handlers | 衔接优先复用 Mayday API |
| 数据 | 现有 DB；规划向 PostgreSQL + Prisma 可选 | 非本刀强制 |
| 鉴权 | Django Auth / Auth.js / Clerk | 按切片选择 |
| 部署 | **Vercel**（前端/BFF）；Django 可分主机或容器 | 选 Vercel 时记录环境变量与音频静态/媒体策略 |
| 协作追踪 | 用 Linear 式「切片/Issue」节奏写纪要编号即可 | 不强制接入 Linear SaaS |

## 四、选型纪律

1. 落在本目录内的选择：**可直接做**，纪要里一笔带过即可。  
2. 跳出本目录（新框架、新托管、新体验范式）：先开协作纪要，产品确认后再做。  
3. 与旧 Mayday 冲突时：**衔接复用优先**，写清「保留 / 替换 / 并行」与回滚点。  
4. 与参考产品撞名或侵权风险的品牌资产（Logo、专有文案）：**禁止照搬**。
