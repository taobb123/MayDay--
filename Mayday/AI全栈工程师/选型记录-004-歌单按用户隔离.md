# 选型记录 004 · 歌单按用户隔离

## 1. 现状摸底

- `Playlist.user` FK + `unique_together (user, name)` 已具备。
- 页面与 API 多处 `Playlist.objects.all()` / `User.objects.first()`。
- 前端 fetch 已带 `credentials: 'same-origin'`，可走 Session。

## 2. 选型与偏差

| 方案 | 本刀 | 原因 |
|------|------|------|
| DRF Token / JWT | 仍用 **SessionAuthentication** | 模板站足够 |
| 公开只读歌单 | 不做 | 产品本刀只要「我的」 |
| 软删除孤儿歌单 | 不迁数据 | 历史歌单归属其当时写入的 user |

## 3. 本刀切片

1. 辅助：`_playlist_login_required` / `_owned_playlist`。
2. 改页面：`playlist_list_view`、`playlist_detail` → `@login_required`；`index` 仅注入当前用户歌单。
3. 改 API：list/create/update/delete/add/remove + ViewSet queryset。
4. 前端：401 时提示登录；`data-user-authenticated` 用真实值。

## 4. 默认假设

- 游客仍可听歌；加歌单须登录。
- `login?next=/playlists/` 支持回跳。

## 5. 本刀交付回写

- `views.py`：歌单页 `@login_required`；API `_json_login_required` + `user=` 过滤；移除 `User.objects.first()`。
- `PlaylistViewSet`：`IsAuthenticated` + `get_queryset` 按用户。
- `LOGIN_URL`；登录表单带 `next`；首页加歌单 401 引导登录。
